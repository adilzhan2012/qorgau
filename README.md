# Qorgau — акустический мониторинг леса

Прототип системы охраны особо охраняемых природных территорий. Датчики на
базе ESP32-S3 слушают лес и передают характеристики звука на сервер, а сервер
решает, что это было: **выстрел, лай собаки, бензопила, транспорт или животное**
— с процентами уверенности и объяснением, почему принято такое решение.

Живая карта датчиков, обновление в реальном времени, распознавание работает
без интернета и без облачных ИИ-сервисов.

### ▶ Открыть сайт: https://adilzhan2012.github.io/qorgau/

Ничего скачивать и устанавливать не нужно — откройте ссылку в **Chrome или Edge**
и нажимайте кнопки со звуками. Чтобы подключить плату, нажмите «ESP32 по USB».

> Учебный проект. Первое развёртывание задумано в Иле-Алатауском национальном
> парке под Алматы.

## Главная идея

**Плата не распознаёт звук — плата его измеряет. Решение принимает сервер.**

ESP32-S3 снимает звук с микрофона INMP441, считает быстрое преобразование
Фурье и вытаскивает из каждого кадра 22 числа:

| Признак | Что означает |
|---|---|
| `rms` | громкость, дБFS |
| `zcr` | частота переходов через ноль — высокая у шипения, низкая у гула |
| `attack` | насколько резко нарос звук — у выстрела почти 1 |
| `harmonic` | есть ли у звука высота тона — у двигателя есть, у выстрела нет |
| `flatness` | «шумность» спектра: 1 — белый шум, 0 — чистый тон |
| `spread` | размазана ли энергия по спектру |
| `bands[16]` | энергия в 16 логарифмических полосах от 60 Гц до 8 кГц |

Эти 22 числа — меньше 200 байт. Именно поэтому схема рассчитана на LoRaWAN:
передавать сам звук не нужно, и датчик может годами работать от батареи.

Логику распознавания можно менять в браузере, **не перепрошивая плату**.

## Как это устроено

```
ESP32-S3 + INMP441
   I2S 16 кГц, кадры по 1024 отсчёта (64 мс)
   → БПФ 512 → 16 полос + громкость, ZCR, атака, высота тона, шумность, разброс
   → строка JSON в USB Serial (115200)
                    ↓
   браузер (Web Serial) ─┐
   микрофон ноутбука ────┼→ классификатор в браузере → карта и карточки
   проигрывание файла ───┘
```

Один набор признаков, один классификатор, три источника звука. Всё считается
на странице — сервера нет, поэтому сайт можно открыть по ссылке.

Сервера нет вообще: сайт — это статические файлы, а классификация считается
в браузере. Поэтому его можно открыть по ссылке на любом ноутбуке.

**Новых зависимостей — ноль.** БПФ и чтение COM-порта написаны вручную,
чтобы перед демонстрацией ничего не пришлось устанавливать.

## Запуск у себя (не обязательно)

Сайт уже опубликован по ссылке выше, и для демонстрации этого достаточно.
Локальный запуск нужен, только если хотите менять код:

```bash
npm install
npm run dev
```

Открыть **http://localhost:3100** в **Chrome или Edge** — Web Serial есть
только в них.

**Ключей, аккаунтов и базы данных не нужно.** Список устройств встроен в код,
распознавание считается прямо в браузере.

### Проверить, что классификатор действительно работает

Страница **[/selftest](https://adilzhan2012.github.io/qorgau/selftest/)** синтезирует шесть звуков с заранее
известными ответами и показывает, что классификатор решил и почему. Сейчас —
6 из 6. Сигналы генерируются заново при каждом обновлении страницы.

## Три способа показать распознавание

| Способ | Как | Когда использовать |
|---|---|---|
| **Кнопки со звуками** | Панель «Датчик» → Выстрел / Собака / Бензопила | Самый надёжный, не зависит от шума и железа |
| **Микрофон ноутбука** | Кнопка «Микрофон», разрешить доступ | Самый живой: хлопок в ладоши → «Выстрел» |
| **ESP32 по USB** | Кнопка «ESP32 по USB», выбрать порт | Настоящее железо |

Подробная пошаговая инструкция с подключением платы и разбором ошибок —
в **[DEMO.md](DEMO.md)**.

### Свои звуки

Положить `.wav` или `.mp3` в `public/audio/` и запустить `npm run audio` —
кнопки появятся сами, код менять не надо. Класс определяется по имени файла:
`gunshot`, `dog`/`лай`, `chainsaw`/`пила`, `vehicle`/`машина`, `ambient`/`лес`.

Файлы в комплекте синтезированы тем же скриптом; свои записи он не
перезаписывает.

## Железо

| Компонент | Роль |
|---|---|
| **ESP32-S3** (N8R2) | слушает и считает признаки |
| **INMP441** | цифровой I2S-микрофон |

Распиновка по умолчанию: `VDD→3V3`, `GND→GND`, `L/R→GND`,
`SCK/BCLK→GPIO4`, `WS/LRCL→GPIO5`, `SD/DOUT→GPIO6`.
Меняется тремя строками `#define` в начале скетча. **Не используйте GPIO 33–37**
— на S3 они заняты PSRAM.

Прошивка при старте сама проверяет микрофон и пишет в порт, что именно не так
с подключением, если что-то не так.

> **Arduino UNO для этой задачи не подходит.** У ATmega328P нет блока I2S,
> 2 КБ оперативной памяти и 16 МГц — БПФ на 512 точек туда не поместится,
> а INMP441 — цифровой микрофон по I2S. Слушает только ESP32-S3.

Скетч: [`firmware/qorgau_sensor/qorgau_sensor.ino`](firmware/qorgau_sensor/qorgau_sensor.ino).
Собирается и на ядре ESP32 2.x, и на 3.x — версия I2S-драйвера выбирается
автоматически.

## Firestore — не нужен

Проект работает полностью автономно. Список из шести устройств с координатами
встроен в код (`src/lib/fallbackDevices.ts`), состояние датчиков живёт в памяти
сервера, распознавание считается на месте. **Никаких ключей, аккаунтов и
интернета для запуска не требуется** — склонировал, `npm install`, `npm run dev`.

Firestore остаётся в коде как необязательное расширение: если положить ключи в
`.env.local`, список устройств будет подтягиваться из облака, и его можно будет
менять без пересборки. Это ответ на вопрос «а как это масштабируется на
настоящий парк с сотней датчиков», а не условие работы.

<details>
<summary>Как подключить Firestore, если всё-таки понадобится</summary>

Скопировать `.env.local.example` в `.env.local` и заполнить ключи из
Firebase Console → Project settings → General → Your apps. Next подставляет
`NEXT_PUBLIC_*` на этапе сборки, поэтому после правки `.env.local` dev-сервер
надо перезапустить.

Базу нужно создать заранее: **Build → Firestore Database → Create database**,
регион `europe-west` или `asia-southeast` (ближайшие к Алматы). Пока базы нет,
все запросы возвращают `NOT_FOUND`, а клиент Firestore повторяет их бесконечно
вместо ошибки — поэтому в приложении стоит таймаут на 10 секунд.

Залить тестовые устройства: `npm run seed`. Правила в `firestore.rules`
разрешают только чтение, поэтому на время засева нужно временно опубликовать
разрешающий ruleset, а потом вернуть обратно.

</details>

## Карты

MapLibre GL, не Mapbox — ни токена, ни аккаунта. Три бесплатных стиля в
`src/lib/mapStyles.ts`: тёмный (Esri Dark Gray Canvas), спутник (Esri World
Imagery) и рельеф (OpenTopoMap).

Подпись об источнике тайлов внизу слева убирать нельзя — это условие
лицензии. Для продакшена стоит взять MapTiler, Stadia или Mapbox: Esri не
публикует явной открытой лицензии на эти адреса.
