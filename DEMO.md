# Qorgau — как показать прототип

Короткая шпаргалка на день демонстрации. Подробности архитектуры — в конце.

---

## 1. Запустить сайт

```bash
npm run dev
```

Открыть **http://localhost:3100** в **Chrome или Edge** (Web Serial есть только там).

Сайт работает даже если Firestore недоступен — список из шести устройств
встроен в код, поэтому «пустого экрана» на демо не будет.

---

## 2. Три способа показать распознавание

### А. Кнопки со звуками — самый надёжный

В панели «Датчик» слева нажать **Выстрел**, **Собака**, **Бензопила**,
**Транспорт** или **Другое**. Звук играет через колонки, сайт его разбирает,
устройство на карте краснеет, появляется вердикт с процентами и объяснением.

Не зависит ни от шума в классе, ни от железа. Начинать показ лучше с этого.

### Б. Микрофон ноутбука — самый живой

Нажать **Микрофон**, разрешить доступ. Теперь ноутбук работает как датчик:
хлопок в ладоши даёт «Выстрел», ровный гул — «Транспорт», звук с телефона —
соответствующий класс. Проценты меняются в реальном времени.

Этим хорошо отвечать на «а если я сам издам звук?».

### В. ESP32-S3 с микрофоном INMP441 — настоящее железо

1. Подключить плату по USB.
2. **Закрыть Монитор порта в Arduino IDE** — COM-порт держит только одна
   программа, и если монитор открыт, браузер порт не получит.
3. На сайте нажать **ESP32 по USB**, выбрать порт в окне Chrome.
4. Индикатор в панели загорится зелёным, пойдут живые данные.

## 3. Прошивка платы

Файл: `firmware/qorgau_sensor/qorgau_sensor.ino`

### Распиновка INMP441 → ESP32-S3

| INMP441 | ESP32-S3 |
|---|---|
| VDD | 3V3 |
| GND | GND |
| L/R | GND (левый канал) |
| SCK (BCLK) | GPIO4 |
| WS (LRCL) | GPIO5 |
| SD (DOUT) | GPIO6 |

Если распаяно иначе — поменять `PIN_BCLK`, `PIN_LRCL`, `PIN_DOUT` в начале скетча.

### Настройки Arduino IDE

> **Сначала надо поставить поддержку ESP32** — сейчас её в вашей Arduino IDE нет,
> установлены только AVR и ESP8266. Файл → Настройки → «Дополнительные ссылки для
> менеджера плат» → добавить
> `https://espressif.github.io/arduino-esp32/package_esp32_index.json`,
> затем Инструменты → Плата → Менеджер плат → найти **esp32** → Установить.
> Скачивание занимает несколько минут — **сделайте это заранее, не в классе.**

| Пункт | Значение |
|---|---|
| Плата | ESP32S3 Dev Module |
| USB CDC On Boot | **Enabled** (иначе Serial не виден) |
| PSRAM | OPI PSRAM |
| Порт | ваш COM-порт |

Скетч собирается и на ядре 2.x, и на 3.x — версия I2S-драйвера выбирается
автоматически.

### Проверка

Открыть Монитор порта на **115200**. Должны идти строки:

```json
{"id":"QRG-001","rms":-52.3,"zcr":0.31,"attack":0.02,"harmonic":0.09,"flatness":0.81,"spread":0.94,"bands":[...]}
```

Если вместо этого повторяется `{"error":"I2S не запустился..."}` — перепроверьте
провода.

### Если браузер не открывает порт

Запасной путь без установки чего-либо:

```bash
npm run bridge -- -List
```

посмотреть порты, затем

```bash
npm run bridge -- -Port COM5
```

## 4. Что отвечать на вопросы

**«Где здесь искусственный интеллект?»**
Плата не распознаёт звук — она его измеряет: громкость, резкость нарастания,
частота переходов через ноль, наличие высоты тона, «шумность» спектра и
энергия в 16 частотных полосах. Эти 22 числа уходят на сервер, и решение
принимает он. Поэтому логику можно править, не перепрошивая плату.

**«Как именно оно отличает выстрел от лая?»**
Показать строку «Почему» под вердиктом — там перечислены признаки, которые
сработали. У выстрела это резкая атака и широкий шумовой спектр; у лая —
энергия в полосе 0.4–2.3 кГц и голосовая гармоника; у бензопилы — устойчивая
высота тона и непрерывность.

**«А это точно работает, а не записано заранее?»**
Открыть `http://localhost:3100/api/selftest` — классификатор прогоняется на
шести синтезированных сигналах с заранее известными ответами. Либо включить
микрофон и предложить учителю самому издать звук.

**«Почему не Arduino UNO?»**
У UNO нет блока I2S, 2 КБ оперативной памяти и 16 МГц. Микрофон INMP441 —
цифровой, по I2S, а быстрое преобразование Фурье на 512 точек в 2 КБ не
поместится. Поэтому слушает ESP32-S3, а UNO в этой схеме не нужен.

**«Что будет в настоящем лесу?»**
Вместо USB — LoRaWAN: плата шлёт те же 22 числа, а это меньше 200 байт, что
как раз укладывается в ограничения LoRa. Звук передавать не нужно, поэтому
устройство может годами работать от батареи.

## 5. Свои звуки

Положить `.wav` или `.mp3` в `public/audio/` — кнопки появятся сами, код менять
не надо. Класс определяется по имени файла: `gunshot`, `dog`/`лай`,
`chainsaw`/`пила`, `vehicle`/`машина`, `ambient`/`лес`.

Файлы в комплекте синтезированы командой `npm run audio`; свои записи их не
перезаписывают.

## 6. Как это устроено

```
ESP32-S3 + INMP441
   I2S 16 кГц, кадры по 1024 отсчёта (64 мс)
   → БПФ 512 → 16 полос + громкость, ZCR, атака, высота тона, шумность, разброс
   → строка JSON в USB Serial (115200)
                    ↓
   браузер (Web Serial) ─┐
   микрофон ноутбука ────┼→ POST /api/ingest → классификатор → память сервера
   проигрывание файла ───┘                            ↓
                                    GET /api/stream (SSE) → карта и карточки
```

Один набор признаков, один классификатор, четыре источника звука.

| Файл | Зачем |
|---|---|
| `src/lib/audio/features.ts` | измерение признаков кадра |
| `src/lib/audio/classify.ts` | **классификатор** — здесь крутить пороги |
| `src/lib/live/store.ts` | состояние датчиков + рассылка по SSE |
| `src/app/api/ingest/route.ts` | приём пакетов от любого источника |
| `src/app/api/selftest/route.ts` | проверка классификатора |
| `firmware/qorgau_sensor/` | прошивка |

Новых зависимостей нет ни одной: БПФ, чтение порта и мост написаны вручную,
чтобы ничего не пришлось устанавливать перед демонстрацией.
